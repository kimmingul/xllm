# xllm 다양성 로드맵 — 미션 정렬 분석과 개선안 (2026-07-11)

> 이 문서는 v0.7.0 시점에서 수행한 미션 정렬 감사와, Codex(`codex@high`)·
> Grok(`grok@high`)과의 2라운드 교차 논쟁, 그리고 승인된 최종 개선안 3가지를
> 기록한다. 논쟁 자체가 xllm(`ask`)으로 수행되었다 — 이 문서는 제품의
> 독푸딩 산출물이기도 하다.

## 1. 미션

AI 에이전틱 코딩 도구(Claude Code / Codex / Grok Build)는 제조사 단일 LLM
프로바이더 락인의 한계를 갖는다. xllm의 목표는 **multi-LLM(로컬 모델 포함)을
최대한 활용해 이 한계를 극복**하는 것이다. 인간이 유전적·사회적 다양성으로
발전하듯, AI도 다양성을 통해 더 견고한 지식 전략 체계를 갖출 수 있다.
다양한 **provider**, 다양한 **model**, 다양한 **effort**를 *적절하게*
활용하는 것이 핵심이다.

## 2. 정렬 판정 (3자 만장일치)

**"다양성 공급(supply)은 구축됐다. 배당(dividend)은 미증명이다."**

- Codex: "진지하고 안전 의식이 있는 멀티-벤더 배관이지, 입증된 다양성
  시스템이 아니다. 합의 깊이 종합은 과장 — JSON은 어휘를 기록할 뿐 주장
  수준의 분류·증거·정오를 기록하지 않는다. 프로토콜 템플릿이지 능력이
  아니다."
- Grok: "다양성 가구(furniture)이지 증명된 전략이 아니다. SCOPE의 성공
  지표는 설치 가능성이지 'multi가 결함을 더 잡는가'가 아니다."
- 자가 진단: OMC를 증거 부재로 비판했으면서 xllm 자신도 결과 증거가 없다
  (Grok: "위선이 된다").

정렬에 **부합하게 구축된 것**: 9개 프로바이더(로컬 3종 포함), 크로스-벤더
강제(동일 벤더 중첩 거부), read-only 안전 모델, ask→propose→exec 사다리,
비용 인지 라우팅(tier/relative_cost)과 역할 핀, scribe 로컬 우선, 합의 깊이
라벨. **미션의 본체가 비어 있는 곳**: 다양성이 실제로 더 나은 결과를 낸다는
측정·증명·회수 장치.

## 4. 논쟁 기록 (2라운드)

### 라운드 1 — 독립 평가 (블라인드)

- **Codex top-3**: ① 통제된 다양성 벤치마크(시딩 결함 + 오류 상관) ② 실행
  가능한 프로바이더 계약("신뢰할 수 있는 어댑터 5개가 거짓말쟁이 9개보다
  낫다") ③ 다양성 인지 순차 라우팅(능력/**계보** 태그 + 과제 하한)
- **Grok top-3**: ① 블라인드 동일 프롬프트 패널 + 쌍별 일치 원장(제품 내
  계측기) ② 합의 기반 순차 비용-최적 에스컬레이션 ③ 로컬 인벤토리 능력
  하한 + 모델 태그 — 그리고 Codex의 계보 태그를 "반증 불가능한 훈련 데이터
  다양성 점수"라고 공격

### 라운드 2 — 반박전 결과

| 쟁점 | 결론 |
|------|------|
| **T1 계약 우선순위** | 상호 양보: Codex "전면 하드닝 선행은 인프라 연극" / Grok "계약 *플로어*는 전제조건, 다개월 순수주의 금지" → **얇게, 먼저** |
| **T2 벤치마크 vs 패널** | 만장일치 순서: **계약 플로어 → 패널+원장(계측기) → 오프라인 벤치마크(인과 증명)**. "원장 없는 벤치마크는 모델 교체 때 죽는 1회성 논문; 벤치마크 없는 패널은 화물숭배 다양성"(Grok); "의미 검증 전의 일치율 대시보드는 장식용 텔레메트리"(Codex) |
| **T3 계보 태그** | Codex 철회("lineage astrology"). 탈상관은 **측정**으로만: 쌍별 일치율 + **과제 조건부 오류 상관**(일치율만으론 부족 — 둘 다 옳아서, 또는 같은 맹점이라 일치할 수 있음). 벤더/모델 출처는 감사 메타데이터로만 보존 |
| **T4 종합자 편향 / 채택 루프** | 해법: **기록과 서사의 분리** — 구조화된 주장/판정 원장이 산문 요약보다 먼저 기록되고, 요약은 원장을 덮어쓸 수 없다. 소수 의견은 일급 아티팩트. 채택 루프는 텔레메트리 디테일이 아니라 **종속 변수**: 개입률, 유익한 번복, 유해한 번복, 기권, 교정된 결정당 비용 |

### 만장일치 비구축 목록

- 다수결 자동 적용 / LLM 의회 / "투표=진리" 엔진 — "상관된 모델들은
  만장일치로 틀릴 수 있다. 합의 자동화는 장식용 신뢰도 메타데이터를 위험한
  권위 기구로 바꾼다"(Codex). 합의는 신뢰도 메타데이터이지 진리가 아니다.
- 손으로 쓴 계보/훈련 데이터 다양성 점수.

## 5. 승인된 최종 개선안 (구축 순서 = 의존성 순서)

### 개선안 1 — 최소 실행 가능 프로바이더 계약 플로어 (v0.8.0)

이후 모든 다양성 실험을 신뢰할 수 있게 만드는 위생 계층. **얇게.**

- 토큰 불요 능력 프로브: 설치된 CLI의 `--help`에서 xllm이 의존하는 플래그
  매트릭스를 검사 → 버전별 기록 → **플래그 드리프트 감지** (조용한 파손의
  최대 원인 차단)
- 구조화된 실패 분류: missing-binary / auth / timeout / transient /
  permanent — stderr 패턴 기반, 순수 함수로 테스트 가능
- 제한된 지터 재시도: transient 클래스에만, 최대 2회
- 옵트인 라이브 인증 미니콜(`contracts --live`): READY ≠ 인증 문제 해소
- doctor / inventory 통합 표시

### 개선안 2 — 블라인드 동일 프롬프트 패널 + 주장 원장 (v0.9.0)

모델-다양성을 프롬프트-다양성과 분리해 **측정**하는 계측기.

- `--panel`: 동일 프롬프트 강제 + 어드바이저별 구조화 판정
  JSON(verdict/key_claims/confidence) 계약 → 결정적 추출
- **원장이 서사보다 먼저**: 어드바이저별 판정·주장 원문 + 쌍별 판정 일치를
  불변 원장(`<state>/panel-ledger.jsonl`)에 기록; 요약은 UX일 뿐 원장을
  덮어쓸 수 없음; 소수 의견 일급 보존
- 누적 쌍별 일치율 행렬(`panel stats`) — 측정된 탈상관의 데이터 원천
- 결정 채택 루프(`panel outcome <run-id> …`): split이 호스트 행동을
  바꿨는지, 유익했는지 기록

### 개선안 3 — 시딩 결함 벤치마크 + 증거 기반 라우팅 (v0.10.0)

다양성 배당의 존재를 **입증하거나 기각**하고, 배당을 라우팅으로 회수.

- 숨긴 결함 시딩 과제로 single-best vs 동일프롬프트-패널 vs 역할분해 통제
  비교: 추가 검출 결함 / 미검출 / 소요시간 / hit-miss 벡터 기반 쌍별 오류
  상관 보고 (라이브 전용, CI 제외)
- 능력 하한: 로컬 모델 크기/유형 태그(모델명 휴리스틱) — 판단 역할
  (security/architecture/verify, 패널 타이브레이크)은 하한 미달 로컬 모델
  거부, 명시적 오버라이드만 허용
- 측정 기반 타이브레이커: split 시 승격 대상 = 능력 하한을 통과하고
  **측정된 일치율이 낮은**(경험적 탈상관) 미참여 프로바이더 — 계보 점수
  없음

## 7. 첫 실측 결과 — 미션 가설의 정직한 검증 (2026-07-11)

`xllm-bench`가 만들어지자마자 미션의 핵심 가설을 falsifiable하게 시험했고,
**불편하지만 값진 답**을 냈다.

### 실행 1 (오염): codex vs ollama:qwen3.6, 4개 과제
- 결과: codex 9/10, qwen **0/10**, 배당 0 → "배당 없음"
- **그러나 무효**: qwen3.6이 CUDA out-of-memory로 로드조차 실패한 것을
  벤치가 "결함 0 검출"로 오채점. 죽은 모델은 탈상관 리뷰어가 아니다. 이
  오염을 벤치가 스스로 드러냈고, 정상 실행 프로바이더만 집계하도록 수정
  (`valid_comparison` 플래그 추가).

### 실행 2 (유효): codex vs grok, 4개 과제 11개 결함
- codex 10/11, grok 10/11 — **둘 다 정확히 같은 결함(`no-fail-return`)만
  놓침**
- **쌍별 오류 상관 = 1.0 (완벽 일치), 공유 맹점 = 1**
- 패널 검출 10/11, **추가 검출 0 → 배당 없음 (valid_comparison: true)**

### 해석 — 미션에 대한 정직한 함의

이것은 미션의 **기각이 아니라 정밀화**다. 앙상블 이론은 "다양성은 오류가
탈상관일 때만 배당을 낸다"고 말한다. 실행 2는 그 조건이 충족되지 **않은**
사례를 실증했다: 서로 다른 벤더(OpenAI codex vs xAI grok)라도 **잘 알려진
결함 클래스에서는 프론티어 모델의 오류가 완벽히 상관**되어, 크로스-벤더
다양성이 여기서는 연극이었다. G2 경고가 데이터로 확인된 것이다.

배당이 나타날 곳은 모델이 실제로 갈리는 지점 — 더 어렵거나 모호한 결함,
설계 판단, 또는 강한 모델과 **측정된 탈상관**(낮은 일치율) 모델의 페어링 —
이다. 그래서 v0.10.0의 나머지 두 축이 필요하다: `panel stats`의 측정
일치율로 탈상관 페어를 **찾고**, `suggestTiebreaker`로 그런 페어에만 예산을
쓴다. **"다양성을 항상 켜라"가 아니라 "탈상관이 측정된 곳에만 켜라."**

가장 중요한 성취: xllm은 이제 자신의 핵심 주장을 반증할 수 있는 계측기를
갖췄고, 그 계측기의 첫 측정은 마케팅이 아니라 불편한 진실이었다. 이것이
OMC 비판("증거 없이 이득 주장")과의 진짜 차별점이다.
